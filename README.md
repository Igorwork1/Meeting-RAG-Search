# Meeting-RAG-Search
**ТЕМА**: Сервис автоматической транскрибации и семантического поиска по записям встреч на основе RAG-архитектуры 
**TOPIC**: Development Of A Service For Automatic Transcription And Semantic Search Of Meeting Recordings Based On RAG Architecture

*курсовая работа, ИИМУП, 1 курс.*
---

# О проекте
Сервис автоматической обработки онлайн-встреч позволяет:

- транскрибировать аудиозаписи совещаний
- сохранять текстовые протоколы встреч
- выполнять семантический поиск по содержанию
- получать ответы на вопросы по обсуждениям

Система реализована на основе архитектуры Retrieval-Augmented Generation (RAG) и объединяет технологии:

- автоматической транскрибации речи
- векторного поиска
- языковых моделей (LLM)
- генерации ответов на основе контекста

Проект разрабатывается для команды стартапа MetaPrompt и ориентирован на автоматизацию работы с содержанием онлайн-встреч.

# Проблема (Pain)

# Проблема (реальный процесс в команде)

В рамках деятельности команды MetaPrompt регулярно проводятся онлайн-встречи, в которых участвуют руководитель проекта, SEO-специалисты и сотрудники различных направлений. Совещания проходят в сервисе Bitrix24.

На встречах обсуждаются:
- текущие задачи
- результаты работы
- возникающие проблемы
- планы и дальнейшие действия

Для того чтобы сохранить содержание встречи, используется следующий процесс.
1. Во время совещания ответственный сотрудник записывает аудио встречи.
2. После окончания встречи аудиофайл выгружается вручную.
3. Файл отправляется в сторонний сервис транскрибации.
4. Полученный текст передается в нейросетевой сервис для суммаризации.
5. Итоговое резюме встречи отправляется в рабочий чат команды.

Параллельно Bitrix24 также записывает встречу и спустя некоторое время отправляет автоматический отчёт по совещанию.

Несмотря на наличие частичной автоматизации, текущий процесс имеет ряд проблем.
- процесс включает несколько отдельных сервисов;
- значительная часть операций выполняется вручную;
- результаты обработки встреч отправляются в чат в виде ссылок;
- отсутствует централизованное хранилище знаний;
- со временем формируется большое количество документов и текстовых файлов;
- поиск нужной информации требует просмотра переписки или ручного поиска по документам.

В результате сотрудники вынуждены тратить дополнительное время на:

- поиск нужной информации в переписке;
- просмотр записей встреч;
- анализ текстовых протоколов.

Таким образом, в текущем процессе отсутствует единая система, которая позволяла бы автоматически транскрибировать встречи, структурировать информацию и выполнять быстрый семантический поиск по их содержанию.

# Решение

Разрабатываемый сервис решает эту проблему за счёт:

- автоматической транскрибации аудио
- централизованного хранения протоколов
- семантического поиска по содержанию
- генерации ответов на основе контекста встречи

Пользователь может задать вопрос:

"Какие задачи были назначены на встрече?"

и получить ответ, сформированный на основе содержания обсуждения.

# Архитектура системы

Сервис реализован по клиент-серверной архитектуре. Pipeline обработки данных:

1. пользователь загружает аудио
2. система выполняет транскрибацию через LLM
3. выполняется резюмирование текста с помощью LLM и сохраняется в базе данных
4. генерируются embeddings
5. embeddings сохраняются в векторный индекс
6. пользователь задаёт вопрос
7. выполняется семантический поиск
8. найденный контекст передаётся в LLM
9. генерируется ответ

# Используемые модели

Сервис использует несколько типов моделей. *Сранивательная таблица*

Задача | Модель
--- | ---
Транскрибация | GigaAM-v3 / OpenaAI Whisper
Суммаризация | Yandex LLM / DeepSeek / Qwen
Embeddings | Giga Embeddings / OpenAI Embeddings
Ответы | Yandex LLM / DeepSeek / Qwen

Архитектура построена таким образом, что модели могут быть заменены без изменения основной логики системы.
